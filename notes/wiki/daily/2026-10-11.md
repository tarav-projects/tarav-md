## Blessings rebuilt on the Actions primitives

The blessing code that request 895 had left beside dismissal had to be
reimplemented with the new primitives. The discussion settled what a
blessing is: one way of closing an action, the one taken although the
situation still exists. Closing an action leaves a typed record, and the
Blessing is that record; it declares assertions, and scoring stays an
independent system.

## The suite becomes the Project's own checks

The separate suite Type built in the morning had a flaw: an action belonged
to the Project a command started from, so a run on a child Project closed
nothing. The User redefined the suite as something a Project has: its
current set of checks. A check belongs to a suite so that something can say
whether it is still happening; a removed check and a check that no longer
triggers are the same case; a crashed check is present. Container Projects
go through their children's suites. Built as request 897; see
[POI visibility, navigation, and blessings](../poi-system.md), section "The
suite is the Project's own set of checks".
