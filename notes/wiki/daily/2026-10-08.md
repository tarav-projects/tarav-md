## Record validation and example namespace paths

The next Record API slice exposes `Type.records.validate_record(value)` and `Type.records.record_example()`. The shared projection and loading paths use namespaced validation. Existing concrete classmethod overrides remain the dispatch points, preserving subclass behavior and `super()` chains; changing that extension mechanism would be a broader migration. The [Record framework](../record-framework.md) records the API boundary and [Impl.Req 868](../../../../tarav-py/notes/live/868-record-namespace-validation-and-examples-impl-req.md) records the implementation and checks.

## Monitor auto-prime pings work again

The account monitor's pings had failed for every Codex account since 2026-09-09 because OpenAI rejects the `gpt-5.4-mini` ping model for ChatGPT-account Codex logins. The User asked for the ping to work again in a simple form.
<!-- tarav.breadcrumb 71ea54013e08a6db24bfb2121474c7e9b9dfbb390ba1c4d1e5943cfa970ef7cb -->

Instead of a new workflow, the existing `auto-prime-zero-limits` workflow was cut down to one rule: every `interval_sec` (10 minutes by default), ping each configured target whose last burst reading is below 5%. Targets stay explicit and are limited to Claude and Codex, so an account such as Claude `om` can be left out. Codex pings now use `gpt-6-luna`. The [Agent accounts monitor](../agent-accounts-monitor.md) note records the rule and [Impl.Req 869](../../../../tarav-py/notes/live/869-auto-prime-burst-threshold-impl-req.md) records the implementation and checks.

## Agent bootstrap and the Tarav System Prompt

The User opened a discussion about the minimal features needed to bootstrap an agent that arrives in a Project developed with Tarav, wanting several redundant ways for the agent to load or search for context, and later a test workflow to evaluate contextualization end to end.
<!-- tarav.breadcrumb 0c5abe2617fa753430210f3d5d14bb84600aabacb19d13608663fc1a9e29a262 -->

The `--ground` module of the `tarav-hugentics` skill could no longer start because Models is disconnected, so the User asked for it to be deleted and re-implemented later. Its source, product, routing and loading entries were removed from the skill, and the mention in `tarav-pkg` was reworded. Other implementation modules still refer to grounding a `Diagram.View`.
<!-- tarav.breadcrumb bdec962d7b3f3730359188afda55c03064482d6d1f3616efedc30315e671133c -->

The first bootstrap feature was then designed: every Project's agents file must carry a Tarav System Prompt shipped with the code base and a Project System Prompt of its own, both checked by built-in Project checks, with the file itself a Skillware product reachable through `project.agents`. The [Agents bootstrap](../agents-bootstrap.md) note records the design, and [Impl.Req 872](../../../../tarav-py/notes/live/872-project-agents-bootstrap-impl-req.md) holds the implementation request, which still has three open questions.
