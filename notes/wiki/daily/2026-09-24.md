## Record Archive navigation and placement

The Archive discussion settled on an Archive-owned tree: `ArchiveEntry` represents a placement and can wrap a Workflow, a stored object, or a path-only grouping. `TaravArchive` is the global starting point for `ls()` and `cd()`; contained objects do not need Archive navigation behavior. This is another way to traverse the Diagram alongside Type and Context relationships.

## Git boundary proposed for the Archive

The current typed Archives initialize separate Git repositories, but the proposed policy moves repository choice into the Archive tree. The Workflow Ship directory must not itself be a repository. Below it, the default would use a parent repository within the Workflow subtree or initialize one at the child being created. Per-level `git-config.json` could override policy; `.gitignore` remains a native file whose path and presence should also be visible through code. This Git design has not been implemented yet.
