## Breadcrumbs as surface attachment points

The discussion generalized the inline Chatlas context comments into
`Tarav.Breadcrumbs`. A Breadcrumb is an opaque stable anchor embedded in a
Product.Surface, not the annotation itself. Workflows attach independent typed
records to that position, allowing context, implementation provenance, and
other semantics to share the same surface point.
<!-- tarav.breadcrumb fb82ff041e44 -->
<!-- tarav.breadcrumb 6b552c7e58a1 -->
<!-- tarav.breadcrumb 852d0bfd3a74 -->

Agents may attach records directly or use a specialized surface workflow. A
workflow can accept cheap temporary annotations, parse and resolve them at the
end of capture, create Breadcrumb and attachment records, then replace the
temporary syntax with the canonical opaque label.
<!-- tarav.breadcrumb f6be2fa7572d -->
<!-- tarav.breadcrumb 6e53eb964ef9 -->
<!-- tarav.breadcrumb b74a1f9d8ced -->

The selected storage direction gives each Breadcrumb ID its own directory.
Stable identity remains in `main.json`; changing position observations append
to JSONL; workflow-owned attachment records remain independent of the
Breadcrumb core.
<!-- tarav.breadcrumb d00517eda4ea -->
<!-- tarav.breadcrumb 6c64d8570237 -->

Position observations use a normal `FilePositionReference`: file and line are
mechanical locator data, while neighboring line fragments are hints ignored by
resolution. The file field may be either a simple path or a typed
`FileReference`, demonstrating the rule that only top-level Tarav Records must
be typed and embedded typing remains application-dependent.
<!-- tarav.breadcrumb 84f69a99d03e -->
<!-- tarav.breadcrumb 363d84a0006f -->
<!-- tarav.breadcrumb be62beff88e4 -->

The design is integrated in the [Breadcrumbs topical note](../breadcrumbs.md).

## Chatlas Normal Model ownership

The discussion promoted the Chatlas Normal Model aggregate itself to a
directory-backed Tarav object. Its normalization module owns the semantic
class, on-demand materialization, and canonical folder representation; being
derived and rebuildable does not make the Model a cache-owned object.
<!-- tarav.breadcrumb b681752ebce0 -->
<!-- tarav.breadcrumb e978054dbd79 -->

Chatlas cache mechanics remain outside the Normal Model module. They may add
an ordinary `cache.json` beside the Model-owned files, but its absence or
invalidity affects cache reuse rather than Normal Model validity. This keeps
the Normal Model at the directory root instead of wrapping it in a cache
entry or treating the cache as a semantic subtype.
<!-- tarav.breadcrumb 043235543980 -->

The design is integrated in the [Chatlas Normal Model topical note](../chatlas-normal-model.md).

## Static Skill context and progressive object context

The discussion separated two context ideas. A Skill `Context.Path` is a
predictable ordered loading path such as description → `SKILL.md` → selected
blocks. SKW can statically check that every path reaching a block contains the
context that block declares it requires. This is a developer check, not an
attempt to observe an agent invocation, and it lets later blocks rely on
earlier contracts without repeating them.
<!-- tarav.breadcrumb d28771d6cedf -->
<!-- tarav.breadcrumb 48b0e8edef68 -->

A separate candidate `Context.Graph.Workflow` gives Tarav Types and objects a
progressively discoverable virtual directory. Static `help()` remains the
small entry point, while class and object `context()` views expose reactive
subtrees assembled from owned, contributed, and discovered material. Entries
may be Records, references, text, projections, collections, or further virtual
directories, navigated with filesystem-like bounded reads.
<!-- tarav.breadcrumb 4ada5d919eab -->
<!-- tarav.breadcrumb 39d778dec99a -->

Durable object context requires durable identity. The proposed
`TaravEntity(TaravObject)` adds a non-rebindable `id: Ship`, while plain
`TaravObject`s retain only computed or session-local object context. Storage
shape remains independent, so an entity may also be a `FileRecord` or
`DirectoryRecord`. Raw Records retain UUID strings; `RecordInterface` exposes
`Ship` values through exact Pydantic round trips.
<!-- tarav.breadcrumb e90c02b7590c -->
<!-- tarav.breadcrumb 2c5edbd70432 -->
<!-- tarav.breadcrumb adb5591566a1 -->
<!-- tarav.breadcrumb f32e0cf170d2 -->

The design is integrated in the [Context Graph](../context-graph.md),
[Skillware](../skillware.md), and [record framework](../record-framework.md)
topical notes.
