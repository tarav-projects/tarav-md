## Design critique and clarifications

The User requested an adversarial review of the wiki's design principles.
The resulting discussion clarified that Tarav's executable code supplies much
of its semantics, while code, data, workflows, and user understanding evolve
together. Capturing before integration, abandoning workflows, and migrating
from retained evidence are deliberate choices. The bootstrap wiki presents
evidence for agent reasoning without requiring a canonical reconciliation.

<!-- tarav.breadcrumb c2c3fec9b8fe0d71638ab64858d727b1da8fea10494e2d5a33596975338576d0 -->

The User accepted that recovery can be costly or impossible, while judging
capture friction to cause greater loss. Human memory, separately tracked code
and data, and replicated repositories can reduce recovery risk. General
navigation is an initial semantic foundation; specialized access workflows
can follow. Diagram connectivity is an intended invariant, and agents may
use their own tools to investigate disconnected components.

The discussion clarified that generation is meant to be harnessed through
evidence and scoring, and that transparent code-based checks remain useful
despite limited coverage. Human review points can deliberately slow even
correct agents so the human knows what is happening and system evolution
remains coupled to human capabilities.

## Context entries and exploration

The Context design separated Context from Archive inheritance. An Archive can
retain a `ContextEntry` as ordinary cargo, while that Context entry wraps its
own typed cargo and supplies context-specific meaning. Runtime entries expose
their name or index even when Archive provides the retained placement; entries
without Archive backing use the same Context navigation interface. Reference
cargo remains a Reference until a caller explicitly resolves it.
<!-- tarav.breadcrumb 676160868b2663632457e316ebeef1056c00628fa0943214faa8ca9bbef6e223 -->
<!-- tarav.breadcrumb a1080f6e188e9ba3c62792d7a124816298f3d79c411de4e8c867e8f79c70f902 -->

The discussion introduced `ContextExplorer` for stateful navigation. Each
Entity has its own context graph; following `context(entry)` enters the cargo's
context with the same explorer and preserves the way back. Direct
`context(entity)` starts a fresh explorer. Runtime entry handles carry their
explorer and origin, while navigation history is not retained in Records.
