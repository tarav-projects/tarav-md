## Typed annotated SKW blocks

SKW now uses `SkwBlock` as its neutral concrete block Type. Its common Record
contains identity, a local label, retained `content`, an optional typed
`objects_index`, and typed workflow-owned `annotations`. Generation and reading
participate through annotations instead of defining separate block identities.
<!-- tarav.breadcrumb 59f52c0ac4d1 -->
<!-- tarav.breadcrumb bfa8fafcf034 -->

Generation context accepts direct typed objects and typed local-index
References. The former SKW prompt interpolation, argument binding,
generation-specific blocks, and untyped context-role wrappers were removed.
Instruction freshness and declared-context freshness now use separate inputs.
<!-- tarav.breadcrumb 892546371390 -->
<!-- tarav.breadcrumb be7f36bb50a6 -->

All 114 blocks in the 37 maintained SKW documents were migrated explicitly.
Both maintained skills rebuild to byte-identical Markdown. Existing valid
baselines were translated, while the 14 context baselines already stale before
the migration remain stale.

## First project operational-library pilot

The g70203 package now exposes a checklist-report workspace for agent-written
Python. It supplies the typed Version, verbatim form, normal projection, exact
report path, and an atomic write operation. The write returns a Tarav
`CheckResult` whose bound POIs adapt g70203's existing report checks; findings
remain reviewable after the artifact is retained.
<!-- tarav.breadcrumb 9fd5ce58e1f4 -->

The pilot keeps the agent's script open-ended and adds no generic workflow
engine. `AGENTS.md` points to a runnable example and the source implementation,
testing the chosen progressive learning path on a real project operation.

## SKW reference resolution checks

SKW now exposes one independently runnable Check for each typed Reference in a
generation-context declaration. Direct References, local object-index targets,
and indexed References share the existing resolution path. A failure emits the
existing `ContextUnresolvable` POI; a successful resolution emits no failure
POI and requires no retained freshness baseline.
<!-- tarav.breadcrumb 7f672070746c -->
<!-- tarav.breadcrumb 365a0c7a417b -->

Document loading no longer follows these targets. It preserves the typed
declarations so broken references remain inspectable by Checks rather than
turning into a generic loading-model failure. Dependent freshness may be
unavailable while the reference Check and unrelated Checks still run.

## SKW Code workflow

Tarav now exposes `tarav.l1.skw.code` as the common source-development
workflow beneath Skillware. Common document, block, annotation, generation,
and reading declaration Types declare that workflow as their Diagram owner;
their established Type Ships and Record schemas remain unchanged.
<!-- tarav.breadcrumb 378c473ed4e4 -->
<!-- tarav.breadcrumb 2f84925bcdc4 -->

The runtime hierarchy is `skillware → skw.code → skw.skills`. Skill packaging,
deployment, loading analysis, and skill-specific components remain in the
specialization. The compiled surface remains ordinary content for its reader;
SKW Records are the developer-side source and harness.
