## Project integration

The user approved inspecting Projects as the next integration point, then
approved implementing the proposed Project entity over existing discovery:
reuse the marker's project_id, keep project.json authoritative, and let Wiki
and Models accept Project objects while retaining their independent ownership.

## Project capabilities and specialization

The discussion then moved from the initial entity integration to dependency
boundaries: minimal workflow functionality should remain separate from
specialized integrations such as Project–Models. The user called for minimal
and more featured Project types now, selected explicitly through
`<ProjectClass>.from_path(path)`, and described project-local subtypes carrying
their own functionality and configuration. This design direction is captured
in [Projects](../projects.md), separately from the earlier implementation.
