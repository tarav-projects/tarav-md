## Reader context and reading dependencies

The discussion developed [Reader.Context.Path](../reader-context-path.md)
for `skw.skills`: expected reader context along declared paths, with per-path,
intersection and union views. Typed links and reading dependencies distinguish
how content is made available, including inlined and referenced delivery.
<!-- tarav.breadcrumb e490862f6e23 -->
<!-- tarav.breadcrumb b638f2d8e687 -->

Blocks declare semantic content, links, inlines and reading requirements.
The path mechanics consume those declarations uniformly; specialized link
blocks are optional. Structural checks report missing dependencies and the
paths that miss them. Verification of the semantic claims belongs to separate
scoring work. This capture records the design; it does not implement it.

## Checks as reusable object capabilities

The discussion established a shared [Checks workflow](../checks-workflow.md)
for reading-path checks and other workflows. Check classes provide reusable
behavior; optional CheckProviders expose appropriate instances via `obj.checks`.
Linters collect those checks and may also construct cross-subject checks or
use explicit pools. One check or one object's checks can run independently
for targeted experiments, without a linter. The POI foundation remains WIP;
the next design step is its minimal shared interface and mechanics.

### Reading-path containment and link availability clarified

The discussion simplified inline content into `contains`: loading A also
loads the content of blocks A contains, recursively, so their annotations
contribute to the reader context. This includes their links, but not the
content behind those links. A contains B links C supplies B and a reference
to C; A links B contains C supplies only a reference to B. Agents may choose
to follow links. Other analyses may traverse them further; this stopping
rule is specific to reading-path availability analysis.

The clarification is captured in
[Reader.Context.Path](../reader-context-path.md#containment-supplies-content-links-supply-references--2026-09-30).
It corrects the earlier review discussion's conflation of exposing a link
with following it. No implementation was changed by this capture.
