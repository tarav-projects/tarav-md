## Lines redesign

The discussion narrowed the Lines workflow to identified Lines and recursive,
typed Blocks. A Line's own Block and ancestor Blocks establish its bounded
authoring context. Typed links from a Block to other Tarav objects can make it
a specification, discussion, or another use, but those links belong to the
broader Diagram and do not change the Line's minimum interpretive scope.
<!-- tarav.breadcrumb 7968d27da534 -->

The implementation gives Lines and Blocks Ships and Record round trips, makes
Block parentage recursive, and removes the old Diagram Models, CLI, and storage
application. The old implementation is recoverable from Git. The current
mechanics and checks are recorded in [the Lines workflow note](../lines-workflow.md)
and [implementation request 929](../../../../tarav-py/notes/live/929-recursive-lines-blocks-impl-req.md).

## Block contents simplification

The user removed the predefined Block topic: the Lines it contains confer its
meaning. Lines and nested Blocks now share one ordered `contents` collection,
so a Line, a nested Block, and another Line can retain that order. Consumers
can filter by type. Records retain the sequence as `content_ships`; the
existing parent and Line scope relationships continue to bound interpretation.
The focused construction, record binding, scoring, and architecture tests
verify the updated implementation.

## Line Notebook and separate Lineage workflow

The discussion established [Line Notebook](../line-notebook.md) as the
proposed persistent home for Blocks and Lines, with a partition and root Block
for each participating Project. Project Types can supply layouts and
operational behavior. The first default layout is typed Discussion and Model
Blocks: Discussion stores reasoning without an implementation obligation;
Model aims to stay current. Typed protections and maintenance checks can be
added through code and integrated with the Project.
<!-- tarav.breadcrumb 86fab48a9d91 -->
<!-- tarav.breadcrumb d1f04ab4336a -->

Legacy design recovery is the first intended use. An Archive Block would
establish historical context; its position beneath Discussion remains open.
Start with the most recent suitable recovered state. The User explicitly
deferred a specialized Block-version system: evolution of anything with a
Ship belongs to a general [History or Lineage workflow](../lineage.md).
Git-backed history and directly stored sequences are possible later
representations. This pass captures those decisions before Notebook or import
implementation.
