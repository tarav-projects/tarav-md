## First principles for the RDF Diagram

The User asked for a contrarian review of the RDF Diagram that Tarav
Center's new Diagram explorer workflow tests. The discussion found a first
principle: the code is the center, and Tarav code produces the RDF graph
(loading Records included); graph technology extracts the semantics, and
Tarav defines only how code connects to the Diagram. RDF normalizes the
language, not the graphs; every edge comes from an object; there cannot be
two core graphs; Ships lead back from the graph to code; the graph is
optional for agents, entered through `tarav context`. See
[RDF Diagram experiment](../rdf-diagram-experiment.md), section
"First principles: code produces the graph".

## The projection contract

The discussion continued with the projection contract: every object has one
hook, `obj.context.triplets()`, returning what it contributes about itself;
the context engine, navigation, search and opening objects by ID are
ordinary Tarav code. See
[RDF Diagram experiment](../rdf-diagram-experiment.md), section
"The projection contract".

## All of Tarav on the graph Context

The User decided the context engine's first usage case and then migrated
all of Tarav to it: every object contributes one type triple by default,
`obj.context()` opens a growing Explorer with history, and every former
Context contribution and view is cut, failing where used, to be rebuilt as
needed. Built as tarav-py request 914. See
[RDF Diagram experiment](../rdf-diagram-experiment.md), section
"The context engine, and all of Tarav migrated".
