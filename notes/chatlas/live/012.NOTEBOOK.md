## Chatlas.Chanels

- `Chatlas.Chanels` is the public derived-analysis layer built around registered chats
- Chatlas should not be only a raw chat storage system; it should become the place where agents extract, publish, search, and reuse analysis over chats
- original chats remain centrally stored and form the hard evidence layer
- analysis artifacts are also centrally stored, flat, and public to agents
- any workspace is only a configuration lens, such as `<name>-workspace.json`, that selects chats, analyses, queries, or views from the central Chatlas corpus
- workspaces should not own the analysis artifacts; they reference centrally stored chat and analysis records
- a channel at a given time has a collection of chats as its target corpus
- a channel accumulates a collection of runs over that corpus
- each run has a prompt, selector state, source chat references, output artifacts, and enough provenance to explain why the run exists
- agents may add new analysis artifacts over chats, provided those artifacts backlink to exact source sessions and, when possible, exact turns or spans
- generated summaries, semantic tags, extracted decisions, issue maps, design traces, file-production provenance, and query result sets can all become analysis artifacts
- code and notes produced by agents should be traceable back to the chat context that produced them and the reason they were produced
- target sessions or analysis scopes may initially be user-defined or user-curated
- automatic Chatlas search can propose candidates, but user-defined targets are the safer starting point
- derived analysis is useful for navigation, recall, embeddings, and candidate discovery, but claims should return to the underlying chat evidence before becoming authoritative
- over time, Chatlas should contain two connected corpora: the registered chat corpus and the public channel corpus around those chats
- the channel corpus becomes reusable project memory without hiding its evidential dependency on chats
- `Chatlas.Chanels` may be an evolution of the existing `Chatlas.View.Model` rather than a wholly separate system
- channels generalize views toward larger, more flexible, prompt-driven analysis programs over changing chat collections
