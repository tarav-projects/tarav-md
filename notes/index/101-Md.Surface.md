# Md.Surface

`Md.Surface` is the markdown-implemented part of a project.

It is the system as expressed through markdown concepts, constraints, relationships, patterns, intended behavior, operational guidance, skills, notes, and coordination surfaces.

## Role

`Md.Surface` gives a name to the part of a project that exists as markdown.

This is useful because agents often need to work on only the markdown-defined system rather than the codebase, runtime, data, or external infrastructure. For example, a user can ask an agent to inspect `Md.Surface:Agentos` and exclude the Python implementation unless it is relevant evidence.

## Agentos Instance

`Md.Surface:Agentos` is the markdown part of the Agentos project itself.

In the current project split, `agentos-md` is the intended home of `Md.Surface:Agentos`. It includes:

- `notes/index/`
- `notes/live/`
- `skills/`
- markdown coordination files such as local `AGENTS.md` files when present
- other markdown-defined surfaces that explain, route, or operationalize Agentos work

## Relation To Index Notes

`Md.Surface` is broader than `Agentos.Index.Notes`.

`Agentos.Index.Notes` is the durable concept-note subsystem inside the markdown surface. For Agentos-style projects, it defines the `Design.Target.Model`.

Other markdown surfaces may support usage, development, operation, or temporary exploration, but durable design truth should converge into `Agentos.Index.Notes`.

## Authority

The markdown surface defines the intended system when the system is md-defined.

For systems with concrete implementations, authority flows:

- `Md.Surface`
- `Canonical.Reference.Implementation`
- other implementations

The reference implementation is valuable evidence and an exemplar, but it is not the authority when it disagrees with the markdown design surface.

## Boundaries

`Md.Surface` is not the whole project by default.

It excludes code, runtime state, package metadata, generated data, and external systems unless those artifacts are themselves markdown surfaces or are being used as evidence for markdown-defined design.
