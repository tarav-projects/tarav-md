# 619 — Match.Template And The Component Registry

## Impl.Abstract

**Scope.** Make `Match.Verbatim` a *derived* artifact in `agentos-py`. Today
`runner.compose_verbatim` builds the judge's prompt from code and the verdict keeps only
`verbatim_hash`, so what a judge saw is unreproducible. After this change the engine
builds a `Match.Template` — a parameterized JSON description naming its parts by content
address — registers every part in a depot-wide `Match.Component.Registry`, renders the
verbatim from the template, and records the template's address on the verdict. Any
verdict can then be rebuilt and checked against its recorded hash without the engine
version that produced it.

A verdict's rebuilt prompt is also reachable from the CLI, so auditing what a judge
actually saw does not require writing Python.

**Out of scope.** No change to what the judge is shown — the rendered bytes must stay
identical. No change to hooks, identity, controls, tickets-as-staging, the answer
contract, or the read side (`report.py`, `poi.py`). No migration of verdicts already on
disk: they carry no template address and stay readable as they are.

**Status.** Executed. All seven slices are implemented and the full `agentos-py` suite
passes at 869 tests, up from 835. Changes are uncommitted for review.

**Source context.** Design landed this session in
`agentos-md/skills/tarav-pkg/design/111-design.md`: the new `Match.Verbatim`,
`Match.Template`, and `Match.Component.Registry` blocks, plus the `Tournament.Verdict`
and `Tournament.Depot` lines that place the template address and the `components/`
directory. This `Impl.Req` realizes those blocks and nothing beyond them.

## Impl.Index

### The Rendered Bytes Are The Invariant

The whole change is a refactor with a hash for a witness. `compose_verbatim` currently
produces an exact string; after the change it must produce the *same* exact string
through a template. That equality is the design's load-bearing property — a verbatim
that cannot be rebuilt byte-for-byte cannot be checked against `verbatim_hash`, and the
registry's whole point evaporates.

So the first executable step is not the registry. It is a test that renders through the
new path and asserts equality with the old one, over several arities, with and without a
ticket, with and without criteria. Everything else lands behind that.

### Components Are Text, The Template Is JSON, Both Are Content

Three component kinds, all registered the same way, all addressed by
`sha256:<hex>` over their exact bytes:

- **`Match.Brief`** — the definition's `question` and optional `criteria`, joined the way
  the current frame joins them. One component, not two: they change together and only
  when the definition changes.
- **`Player.Presentation`** — one per player, the exact string `present_player` returned.
  This is where dedup pays: a player meets many opponents and its presentation is written
  once for the whole depot.
- **`Match.Footnote.Template`** — the engine's trailing frame with its per-run values
  still unbound: the ranking instruction and the two submit commands. One registration
  per engine version.

The `Match.Template` is registered by the same mechanism, so the verdict carries one
address and that address resolves the whole run. It dedups almost nothing — it names a
presented order that is randomized per run — and that is fine; it costs one small object
and buys a single pointer on the envelope.

Position labels are generated by the renderer from arity. They are engine frame but
interleave the presentations rather than trailing them, so they belong to no component.

### Per-Run Values Ride Beside The Template, Not Inside It

The footnote template has three holes: the ticket id, the depot root as it appears in the
rendered command, and the arity in `Rank all N candidates`. Arity derives from
`len(players)` and the ticket is already on the envelope. **The depot root is not
recorded anywhere today**, and it appears verbatim in the judge's prompt — so a depot
that moves would silently fail every reassembly.

This is the one place the implementation needs something the index does not yet say.
Decision: the verdict envelope gains `template_bindings`, a small dict holding exactly the
values the renderer needs that are not otherwise derivable. It keeps
`Match.Template`'s stated property — per-run values are bound at render time and not
restated in the template — while making reassembly total rather than
environment-dependent. **This should get an index line after execution.**

### Registration Is Idempotent And Concurrent

`run_pool` fans matches out over a `ThreadPoolExecutor`, so several matches register
components into one registry at once. Content addressing makes the writes idempotent by
construction, but they must also be atomic: write to a temp file in the same directory
and `os.replace` onto the final name. A reader must never observe a half-written
component. Writing a component already present is a no-op that does not touch the file.

### Reassembly Is A Read, Not A Repair

`reassemble(store, verdict)` resolves the template address, resolves each component
address, renders with the recorded bindings, and returns the text. A caller compares its
hash to `verbatim_hash` itself. The function does not verify, does not repair, and does
not fall back — a missing component is an error naming the address, because a silent
partial rebuild is worse than none. Verdicts written before this change carry no template
address and raise a distinct, named error rather than a generic lookup failure.

## Execution.Plan

### Slice 1 — The renderer produces today's bytes (RED first) — **Done**

Add `src/agentos/tournament/template.py` with pure functions and no I/O:
`build_template(...) -> dict`, `render_template(template, components, bindings) -> str`,
where `components` maps address to text. Write the equality test **first** and watch it
fail: for a matrix of arities (2, 4, 26), criteria present and absent, ticket present and
absent, `render_template(build_template(...))` equals the current `compose_verbatim(...)`
output exactly.

- **Result:** a template round-trip that reproduces the current frame byte-for-byte.
- **Check:** the new equality test passes; the existing suite is untouched and still green.

### Slice 2 — The component registry — **Done**

Add `src/agentos/tournament/components.py`: `ComponentRegistry(root)` over
`<depot>/components/`, with `put(data: bytes) -> str`, `get(address) -> bytes`,
`has(address) -> bool`. Address is `sha256:<hex>`; layout shards by the first two hex
characters. Writes go through a temp file and `os.replace`.

- **Result:** an idempotent content-addressed store inside the depot.
- **Check:** tests for round-trip, identical content yielding one address and one file,
  a repeat `put` leaving the file's mtime untouched, a missing `get` raising a named
  error, and concurrent `put` of the same content from several threads producing exactly
  one file.

### Slice 3 — `compose_verbatim` goes through the template — **Done**

Rewrite `compose_verbatim` to build the template, register its components, render, and
return both the text and the template address. Add `DEFAULT_COMPONENTS_DIRNAME` to
`depot.py` and its docstring's directory list.

- **Result:** every composed verbatim leaves its parts in the registry.
- **Check:** the full existing suite passes unchanged — no test asserting prompt text may
  need editing, which is the point. Plus a test that composing the same match twice
  registers each component once.

### Slice 4 — The template address reaches the verdict — **Done**

Thread `template` and `template_bindings` through: `MatchResult`, `Ticket`
(defaulted so pre-field ticket files still load), `TicketStore.mint`,
`store.append_verdict`, `ENVELOPE_FIELDS` in `model.py`, and both `submit` paths in
`commands.py`. Emit both on the preview JSON and the `_run_row` envelope.

- **Result:** a verdict names the template that produced its run.
- **Check:** a live end-to-end `preview` + hand `submit` puts a resolvable template
  address on the verdict; a ticket file written without the fields loads with them empty;
  a consumer slot may not shadow either field.

### Slice 5 — Reassembly — **Done**

Add `reassemble(store, verdict) -> str` to `template.py`. Resolve, render, return.
Raise `TemplateMissingError` for a verdict with no template address and
`ComponentMissingError` naming the address for an unresolvable part.

- **Result:** any verdict written after slice 4 rebuilds its exact prompt.
- **Check:** RED-then-GREEN — reassembling a recorded verdict reproduces a string whose
  sha256 equals the recorded `verbatim_hash`; a pre-change verdict raises the named
  error; a registry with one component deleted raises the other, naming it.

### Slice 6 — Documentation — **Done**

Update `agentos-py/AGENTS.md`'s Tournament System section: the prompt-composition bullet
becomes template-mediated, the depot bullet gains `components/`, and reassembly plus its
`template_bindings` caveat get a bullet. Update the `$kw` headers on the touched modules.

- **Result:** the doc matches the code in the same unit of work, per `AGENTS.md`'s own
  rule.
- **Check:** read back; every claim traceable to a slice above.

### Slice 7 — `agentos tournament verbatim` — **Done**

Add `verbatim --tournament <id> --verdict <record-id> [--json]` to `commands.py` and
register it in `agentos-cli`. It reassembles and prints the exact prompt that verdict's
judge received, plus whether the rebuilt hash matches the recorded one.

- **Result:** auditing a judge's prompt is a shell command.
- **Check:** the command reproduces a known verdict's prompt; a pre-change verdict exits
  with the named error rather than a traceback; `--json` carries `verbatim`,
  `verbatim_hash`, `rebuilt_hash`, and `matches`.

### Ordering and dependencies

1 → 2 → 3 → 4 → 5 → 6 → 7, strictly. Slice 1 is pure and provable alone; slice 3 cannot land
before the registry exists; slice 5 needs the address on the record.

### Deviation triggers

- **The equality test cannot be made to pass** for some input the current frame handles.
  Stop. It means the frame has a code-shaped dependency that is not expressible as data,
  and the design needs revisiting before any of this lands.
- **`template_bindings` turns out to need more than ticket id and depot root.** Record
  each addition and why; if it starts to look like the whole run, the split between
  template and bindings is wrong.
- **An existing test asserts prompt bytes and fails in slice 3.** That is a real
  regression, not a test to update.

### Acceptance signals

- The full `agentos-py` suite passes, with no existing assertion edited to accommodate
  the change.
- A verdict produced through `preview` + `submit` reassembles to a string whose hash
  equals its recorded `verbatim_hash`.
- The registry holds one file per distinct component across a multi-match run, verifiable
  by counting files against distinct players.

**D2 — slice 2's module landed inside slice 1.** `template.py` exposes

The registry's own tests still followed as slice 2. Same shape as 618's D1.

**D3 — the concurrency test found a real bug.** The first `put` built its temp filename
from `id(data)`, which CPython interns to the same value for an identical literal across
threads; every racing writer therefore picked the same temp name and one consumed
another's file. Fixed with a per-writer `uuid4` suffix. The test was written before the
implementation, which is why it surfaced at all.

**D1 — `template_bindings` is ahead of the index.** The envelope field is required for
total reassembly and is not stated in `Match.Template` or `Tournament.Verdict`. Recorded
here deliberately; capture it after execution rather than inventing an index line from
inside an implementation. Still open after execution — `Match.Template` and
`Tournament.Verdict` both want a line about it.
