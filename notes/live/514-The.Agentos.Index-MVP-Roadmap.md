# The.Agentos.Index — MVP Roadmap

Detailed roadmap for building the minimum viable implementation of the Agentos Index skill system.

Companion to: `513-The.Agentos.Index.md` (design source)

Status: **closed — MVP implemented (Phases 1-5 complete)**

---

## MVP Goal

A working skill system that enables the `Index.Eval.Loop` in real conversations:

- agent detects `Dotted.Notation` → fires `Index.Call` → resolves or parks
- agent can load index blocks for grounding
- agent can propose and write to the index through a gated path
- all backed by a meta skill containing the full design reference

### 2.2 — Design `agentos-index-trigger`

- define the linting step: what checks run before commit?

## Dependencies & Risks

### Dependencies

- `agentos mdblocks` CLI must be stable (it is — already implemented)
- `agentos prefix next` must work reliably (it does)
- skill loading infrastructure must support `references/` (it does)

### Risks

- **trigger prompt size**: if `agentos-index-trigger` grows too large, it defeats the purpose of being lightweight
- **resolution quality**: `Index.Name.Resolution` with just registry scan may be too brittle; LLM judgment adds non-determinism
- **eval loop interruption**: if the loop interrupts conversation flow too aggressively, users will disable it
- **write gating friction**: if the approval flow is too heavy, agents won't propose writes and concepts won't get captured

### Mitigations

- keep trigger skill ruthlessly minimal — resist feature creep
- start with registry-scan + agent judgment for resolution; formalize later if needed
- make grounding silent by default (context load without explicit announcement) unless the user asks
- make write proposals concise and batch-friendly (propose multiple at once when appropriate)

****

## Success Criteria

The MVP is successful when:

1. An agent in a conversation with an active index reliably detects Dotted.Names and grounds from the index
2. New concepts that emerge in conversation can flow through the write path into the index within the same session
3. The design in `agentos-index` references is self-consistent and complete enough that an agent loading it can operate the eval loop without additional instruction
4. The prompt footprint of `agentos-index-trigger` is small enough to be always-on without noticeable context cost
5. A human reading the index can still browse and understand it without needing the agent runtime
