## Index.Block.Approval.Check

- [DF] `Index.Block.Approval.Check` is an `Index.Linter` check that verifies every block changed by an index edit has its own `User.Stamp::Approval` in the supplied Chatlas session ^c20260725-28u
- [DF] `User.Stamp::Approval` is the user-authored event `::approve <Block.Name>` accepting one exact candidate change for that block ^c20260725-28u
- [CT] candidate changes are reviewed one block at a time, even when several approved blocks will be landed together ^c20260725-28u
- [CT] every changed block requires a distinct matching approval event; cluster-level approval does not satisfy the check ^c20260725-28u
- [CT] the changed block’s approval anchor must resolve to its matching user event ^c20260725-28u
- [CT] changing the candidate after approval invalidates its stamp and requires a new approval event ^c20260725-28u
- [DC] the linter receives the current Chatlas session identity and evaluates the edit’s changed-block set ^c20260725-28u
- [DC] a missing, stale, mismatched, or non-user approval raises a POI identifying the affected block ^c20260725-28u
- [PR] the check makes block-level review authority mechanically auditable after every index edit ^c20260725-28u
